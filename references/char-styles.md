# 글자 모양(charPr)·문단 모양(paraPr) 다루기

본문의 모든 글자는 `<hp:run charPrIDRef="N">`으로 **미리 정의된 글자모양 N번을
가리킬 뿐**이다. 글꼴·크기·색을 바꾸려면 run 안에 스타일을 쓰는 게 아니라
header.xml에 charPr를 정의하고 그 id를 참조한다. 문단 정렬·여백도 마찬가지로
`<hp:p paraPrIDRef="N">`이다.

## 단위 환산 (외우고 있을 것)

| 항목 | 표기 | 예 |
|---|---|---|
| 글자 크기 | `height` = pt × 100 | 12pt → `height="1200"` |
| 길이(여백/너비) | HWPUNIT, 1mm = 283.465 | 10mm → `2835` |
| 장평 | `<hh:ratio>` 퍼센트 | 96% → `hangul="96"` |
| 자간 | `<hh:spacing>` 퍼센트 | -5% → `hangul="-5"` |
| 색 | `textColor` 16진수 | `#FF0000` |
| 굵게/기울임 | 자식 태그 유무 | `<hh:bold/>` `<hh:italic/>` |
| 밑줄 | `<hh:underline type="SOLID">` | 끄면 `type="NONE"` |

`<hh:ratio>` `<hh:spacing>` 등은 **hangul/latin/hanja/japanese/other/symbol/user
7개 속성을 전부** 써야 한다. 하나라도 빠지면 한글이 문서를 거부한다.

## skeleton에 이미 준비된 글자모양

새로 만들기 전에 여기서 먼저 찾을 것. 대부분 이 안에서 해결된다.

| id | 크기 | 글꼴 | 특징 | 주 용도 |
|---|---|---|---|---|
| 11 | 12pt | 나눔고딕 | — | **개념 본문·문제 지문 기본** |
| 15 | 12pt | 나눔고딕 | **굵게** `#FF0000` | 용어 강조, 주의 문구 |
| 27 | 12pt | 나눔고딕 | — | 본문 대체 슬롯 |
| 14 | 12pt | 나눔바른펜 | 장평 96 | **표 안 숫자·수식 라벨** |
| 32 | 12pt | 나눔바른펜 | 굵게, 장평 96 | 표 머리행 |
| 24/25/26 | 9/8/7pt | 나눔바른펜 | 장평 96 | 좁은 표 칸, 각주 |
| 17/21/28 | 14/15/16pt | 나눔바른펜 | 장평 96 | 큰 숫자, 페이지 번호 |
| 30/31 | 16pt | 나눔손글씨 펜 | 굵게 / 보통 | 손글씨 느낌 제목 |
| 13 | 12pt | 나눔바른고딕 | 굵게 | 소제목 |
| 8/9/10 | 8.5/10/11pt | Calibri | — | 영문·숫자 |
| 12 | 11pt | Times New Roman | — | 영문 세리프 |
| 18/19/16/22 | 7/4/2/5pt | — | — | **간격 조절용 빈 문단** |
| 7 | 1pt | 함초롬바탕 | — | 배경 이미지 문단 (건드리지 말 것) |

> 대략 1.4mm. 정확한 계산식은 `layout-rules.md` 참조.

## 새 글자모양이 필요할 때

직접 XML을 붙여넣지 말고 스크립트로 추가한다. `itemCnt` 갱신과 글꼴 자동 등록,
lang별 id 매핑, XML 유효성 검사까지 한 번에 처리한다.

```bash
python3 scripts/apply_style.py Contents/header.xml --add-charpr \
  '{"font":"나눔스퀘어","latin":"Times New Roman","pt":16,"bold":true,"color":"#1F3864"}'
# → add-charpr → charPrIDRef="33"
```

지정 가능한 키: `font`(필수), `pt`(필수), `latin`, `bold`, `italic`, `underline`,
`color`, `ratio`(장평), `spacing`(자간), `borderFill`.
`font`가 아직 등록 안 된 글꼴이면 자동으로 fontfaces에 추가된다. 단 **반드시
`references/fonts.md`의 설치 목록 안에 있는 이름**이어야 한다.

출력된 id를 그대로 본문에 쓴다:
```xml
<hp:run charPrIDRef="33"><hp:t>연속확률변수의 뜻</hp:t></hp:run>
```

## 문단 모양(paraPr)은 기존 것을 재사용한다

paraPr는 정렬·여백·줄간격·탭 정의가 얽혀 있어 새로 만들면 사고가 잘 난다.
skeleton의 검증된 것들:

| id | 정렬 | 왼여백 | 줄간격 | 용도 |
|---|---|---|---|---|
| 21 | LEFT | 0 | 100% | 배경 이미지 문단, 빈 문단 |
| 22 | LEFT | 12.35mm | 150% | 개념 본문 |
| 23 | JUSTIFY | 13.05mm | 150% | 문제 지문(양쪽 정렬) |
| 24 | LEFT | 1.8mm | 100% | 표 셀 |
| 25 | LEFT | 10.23mm | 100% | 선택지 줄 |
| 27 | CENTER | 0 | 150% | 가운데 정렬(수식·표 제목) |
| 33 | LEFT | 0 | 100% | 여백 없는 기본 |

가로 위치를 미세 조정할 땐 새 paraPr를 만들기보다 **기존 id를 쓰고 텍스트 앞에
공백을 넣거나, 표의 셀 너비로 맞추는 쪽**이 안전하다.

## 서식 분석 워크플로우

사용자가 **"이 파일이랑 똑같은 서식으로"** 또는 **"여기 쓰인 글꼴이 뭐야"**라고
하면 추측하지 말고 먼저 뽑아본다.

```bash
# 전체 서식 인벤토리
python3 scripts/inspect_style.py 기존파일.hwpx

# 본문에서 실제 쓰인 것만 (보통 이쪽이 유용 — 정의만 되고 안 쓰인 게 대부분이다)
python3 scripts/inspect_style.py 기존파일.hwpx --used

# 기계 판독용
python3 scripts/inspect_style.py 기존파일.hwpx --json
```

출력에는 글꼴 슬롯, charPr별 크기·글꼴·색·굵기·장평·자간, **각 charPr가 몇 번
쓰였는지와 그 샘플 텍스트**, paraPr별 정렬·여백·줄간격이 나온다. 샘플 텍스트를
보면 "12pt 나눔고딕 = 본문", "12pt 빨강 굵게 = 용어 강조" 처럼 역할을 바로 알 수 있다.

분석 결과는 사용자에게 표로 정리해 보고한 뒤, 그 서식을 그대로 새 문서에
적용한다. 기존 문서의 header.xml을 통째로 가져다 쓰면 가장 정확하지만, 그 경우
paraPr/charPr id 체계가 skeleton과 달라지므로 **section XML의 IDRef를 전부 새
체계에 맞춰 다시 매핑**해야 한다. 대개는 skeleton을 유지한 채 필요한 글꼴만
`--set-face`로 갈아끼우는 쪽이 빠르고 안전하다.

## 사용자가 서식을 직접 지정할 때

"제목은 나눔스퀘어 16pt 굵게 남색, 본문은 나눔고딕 11pt" 같은 요청이 오면:

1. 글꼴 이름을 `references/fonts.md` 목록과 대조한다. 없으면 **만들기 전에**
   가장 가까운 대안을 제시하고 확인받는다(없는 글꼴은 조용히 대체되어 레이아웃이 깨진다).
2. 기존 charPr 표에서 조건이 맞는 게 있으면 그대로 쓴다.
3. 없으면 `--add-charpr`로 추가하고, 반환된 id를 section XML에 쓴다.
4. 작업 후 `validate_hwpx.py`로 검증한다.

크기를 바꾸면 줄 높이가 바뀌어 페이지 아래 요소가 밀린다. 본문 크기를 변경한
경우에는 반드시 `layout-rules.md`의 빈 문단 계산을 다시 하고, 사용자에게
"인쇄 PDF를 주시면 위치를 재측정하겠다"고 안내한다.
